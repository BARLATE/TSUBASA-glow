# Threads のワークフロー（threads-workflow.md）

2026-11-10 決定: Threads を先に始め、Instagram（リール）は後で。
収益の形: 商品のおすすめ説明 ＋ 楽天アフィリエイトの URL を Threads に投稿 → URL 先で購入 → 報酬。

## 前提（要確認の物は確かめてから使う）

- アフィリエイト: 楽天アフィリエイトから始める（2026-11-10 時点で登録作業中）。Amazon アソシエイトは楽天に慣れてから。
- PR 表示: アフィリエイト URL を含む投稿には必ず「#PR」などの表示を入れる（ステマ規制）。
- 1投稿の文字数の上限・リンクの扱いなど Threads の仕様: {{要確認: 投稿前に公式ヘルプで確認}}
- 楽天アフィリエイトの規約（SNS への掲載、自己購入の扱いなど）: {{要確認: 規約で確認}}
- 本人が使っていない商品は「使った」と書かない。クチコミは「楽天のクチコミ◯件を調べたら」と出典付きで他の人の声として紹介する。

## 担当（28人のうち Threads で使う15人）

| 工程 | 担当 | Threads での仕事 |
| --- | --- | --- |
| 受付・進行 | 28 進行管理 | 受付の質問、担当への受け渡し、承認ゲート |
| リサーチ | 01 市場調査 | 商品とクチコミ（点数・件数・良い声・気になる声。出典と確認日） |
| | 04 トレンド調査 | 季節の悩み・話題の成分（出典付き） |
| | 05 視聴者分析 | 悩みと言葉（実データが出るまでは仮説） |
| 企画 | 06 企画立案 | 投稿案を5つ以上（商品・切り口・型） |
| | 07 テーマ選定 | 1本に絞る【承認ゲート1】 |
| 投稿文 | 08 構成設計 | 1投稿か、つなげる投稿（スレッド）か。各投稿の役割 |
| | 09 フック作成 | 最初の1行（フィードで止まる行）。hookscore.py で採点 |
| | 10 台本作成 | 本文を書く（読み上げではなく、読む文として） |
| | 12 CTA設計 | URL の置き場所、PR 表示、誘導の1文 |
| チェック | 14 事実確認 | 点数・件数・価格・成分の出典を確かめる |
| | 15 表現チェック | 薬機法・PR 表示・けなす言い方・detect.py【承認ゲート2】 |
| 投稿 | 22 品質確認 | quality.md のチェックリスト（動画の項目は除く） |
| | 23 投稿管理 | 投稿日時の案と手順【承認ゲート3】→ ユーザーが投稿 |
| 分析・改善 | 25 コメント分析・26 数値分析・27 改善提案 | 48時間後に数字を貼ってもらう |

画像を付ける投稿の時だけ 17 画像生成・18 図解作成を使う。
11 タイトル・16 素材収集・19 字幕・20 動画編集・21 音声調整・24 キャプションは、Threads では休み。

## 流れ

```
受付(28) → 01/04/05 リサーチ（30日以内の結果は再利用）
→ 06 企画 → 07 テーマ【承認1】
→ 08 構成 → 09 フック → 10 本文 → 12 CTA
→ 14 事実 → 15 表現【承認2】（差し戻しは 10 へ、最大2回）
→ 22 品質確認 → 23 投稿管理【承認3】→ ユーザーが Threads に投稿
→ 48時間後 25 → 26 → 27 → 次の企画へ
```

## 投稿文の出力ファイル（作業フォルダ）

- `10-post.md`: 投稿文（1投稿ずつ区切る。文字数を各投稿の下に書く）
- `12-cta.md`: URL（`{{楽天のリンク}}`）・PR 表示・誘導の文

## 確認する指標（Threads 版）

| 段 | 数字 | 出所 |
| --- | --- | --- |
| 表示 | 閲覧数 | Threads のインサイト |
| 反応 | いいね・返信・再投稿・引用 | Threads |
| クリック | リンクのクリック数 | 楽天アフィリエイトの管理画面 |
| 収益 | 購入件数・報酬額 | 楽天アフィリエイトの管理画面 |

数字はユーザーが貼った物だけを使う。
