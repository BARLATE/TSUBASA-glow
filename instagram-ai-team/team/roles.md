## ① リサーチ

### R01 市場調査
- **目的**: アカウントが属するジャンルの市場規模・需要・季節性を把握し、企画の方向性の根拠をつくる。
- **入力**: アカウント概要（ジャンル・ターゲット）【未確定】、`rules/kpi.md`
- **作業手順**:
  1. ジャンルのキーワードを洗い出す
  2. 公開統計・業界レポート・検索ボリュームなどの一次情報を収集する
  3. 需要の高いテーマ・季節要因・未充足ニーズを整理する
  4. 出典のない数値は除外するか `【要確認】` を付ける
- **出力形式**: `research/market_YYYYMMDD.md`（要約3行、需要テーマ一覧、季節カレンダー、出典一覧）
- **完了条件**: すべての数値に出典と取得日があり、需要テーマが5件以上ある
- **引き継ぎ**: → R06 企画立案（需要テーマ、季節要因、未充足ニーズ）
- **追加タスク**: 販売するnoteのテーマ候補の根拠となる需要を調べる（詳細は `rules/note-product.md`）

### R02 競合調査
- **目的**: 競合アカウントの勝ちパターンと空白領域を特定する。
- **入力**: 競合アカウント一覧【未確定：オーナー指定 or R01から候補提示→承認】
- **作業手順**:
  1. 競合のプロフィール・投稿頻度・投稿形式を記録する
  2. 伸びている投稿の共通点（フック・尺・構成・テーマ）を抽出する
  3. 競合がやっていない領域（ポジショニングの空白）を整理する
- **出力形式**: `research/competitors_YYYYMMDD.md`（競合比較表、勝ちパターン、空白領域）
- **完了条件**: 指定された全競合について比較表が埋まり、空白領域の仮説が3件以上ある
- **引き継ぎ**: → R06 企画立案（勝ちパターン、空白領域）、→ R03 投稿収集（調査対象のアカウント）
- **責任範囲**: 「アカウント単位」の分析を担当する。個別投稿の収集はR03が担当。

### R03 投稿収集
- **目的**: 参考になる個別投稿を集め、分析可能なデータベースにする。
- **入力**: R02の対象アカウント、R04のトレンドキーワード
- **作業手順**:
  1. 対象の投稿URL・公開日・形式・公開されている反応数を記録する
  2. フック（冒頭3秒）・構成・尺・CTAを文字に起こす
  3. タグ付け（テーマ／フック型／構成型）
- **出力形式**: `research/posts_db.csv`（URL, 日付, アカウント, 形式, 尺, フック, 構成, CTA, 反応数, 取得日, タグ）
- **完了条件**: 1回の依頼につき【未確定：件数】件を収集し、すべてにURLと取得日がある
- **引き継ぎ**: → R08 構成設計 / R09 フック作成（型の参考例）
- **注意**: 取得方法はInstagramの利用規約に沿う。非公開の数値は推測しない。

### R04 トレンド調査
- **目的**: 今伸びている音源・フォーマット・話題を把握する。
- **入力**: ジャンルのキーワード、R03の投稿DB
- **作業手順**:
  1. 直近【未確定：期間】の流行フォーマット・音源・話題を収集する
  2. アカウントとの相性と、`rules/ng-themes.md` への抵触有無を判定する
  3. 旬の期限（いつまで使えそうか）を見積もり、根拠を記載する
- **出力形式**: `research/trends_YYYYMMDD.md`（トレンド名, 種類, 根拠URL, 相性◎○△, 期限の見込み）
- **完了条件**: すべてのトレンドに根拠URLがあり、NG判定が済んでいる
- **引き継ぎ**: → R06 企画立案、→ R21 音声調整（音源候補）

### R05 視聴者分析
- **目的**: フォロワー・ターゲットの属性、悩み、反応する言葉を明確にする。
- **入力**: Instagramインサイト（オーナー提供）【未確定】、R25のコメント分析
- **作業手順**:
  1. 属性（年齢・性別・地域・アクティブ時間帯）をインサイトから転記する（推測しない）
  2. コメント・DM・保存傾向から悩みと欲求を抽出する
  3. ペルソナを1〜3人作成する（根拠データを併記）
- **出力形式**: `research/audience.md`（属性表、ペルソナ、悩みリスト、反応ワード）
- **完了条件**: ペルソナの各項目に根拠データの参照がある
- **引き継ぎ**: → R06 企画立案、→ R24 投稿管理（アクティブ時間帯）

## ② 企画

### R06 企画立案
- **目的**: リサーチ結果から、KPIに貢献する企画案を複数つくる。
- **入力**: R01〜R05の出力、`rules/ng-themes.md`、`rules/kpi.md`
- **作業手順**:
  1. 需要×勝ちパターン×空白領域の組み合わせで企画案を作る
  2. 各案に「狙うKPI」「ターゲット」「根拠」を付ける
  3. NG条件に該当しないか自己チェックする
- **出力形式**: `plans/ideas_YYYYMMDD.md`（企画名, 概要, 狙うKPI, ターゲット, 根拠, 想定形式）
- **完了条件**: 5案以上あり、全案がNGチェック済み
- **引き継ぎ**: → R07 テーマ選定
- **責任範囲**: 「案を広げる」担当。採用の判断はしない（R07が担当）。

### R07 テーマ選定
- **目的**: 企画案を評価し、今回制作する1本を決める。
- **入力**: R06の企画案、投稿カレンダー（R28）
- **作業手順**:
  1. 評価軸（KPI貢献・制作難度・旬・既存投稿との重複）で採点する
  2. 上位案と選定理由を作成する
  3. **オーナーの承認を取る**（承認ゲートG1）
- **出力形式**: `plans/selected_<id>.md`（採用テーマ、選定理由、狙うKPI、ターゲット、参考投稿）
- **完了条件**: オーナーが承認済み
- **引き継ぎ**: → R08 構成設計（採用テーマの一式）

## ③ 台本

### R08 構成設計
- **目的**: 尺と視聴維持を考えた骨組み（秒単位）をつくる。
- **入力**: R07の採用テーマ、`rules/tone-and-structure.md`、R03の構成型
- **作業手順**:
  1. 尺【未確定：標準秒数】に合わせてブロック分けする（フック／本編／オチ／CTA）
  2. 各ブロックの役割・秒数・見せ方（テロップ・図解・実写）を決める
- **出力形式**: `scripts/<id>/structure.md`（ブロック表：秒数, 役割, 内容の要点, 映像の指定）
- **完了条件**: 合計の尺が規定内に収まり、各ブロックに役割がある
- **引き継ぎ**: → R09・R10・R11・R12（並行作業）
- **責任範囲**: 「骨組み」だけを担当する。文章はR10、冒頭の文言はR09。

### R09 フック作成
- **目的**: 冒頭の約3秒で離脱を防ぐ一言と映像を作る。
- **入力**: R08の構成、R03のフック型、R05の反応ワード
- **作業手順**: 型ごとに案を作る（問いかけ／意外性／結論先出し など）→ NG表現をチェック → 推奨案に理由を付ける
- **出力形式**: `scripts/<id>/hooks.md`（案5つ、型、推奨順、理由）
- **完了条件**: 5案あり、推奨1案が決まっている
- **引き継ぎ**: → R10 台本作成（推奨フック）

### R10 台本作成
- **目的**: 構成とフックをもとに、読み上げ原稿と映像指示を書く。
- **入力**: R08の構成、R09のフック、`rules/tone-and-structure.md`（参考台本）
- **作業手順**: ブロックごとにナレーション／テロップ／映像指示を書く → 事実・数値には出典を付け、ないものは `【要確認】` → 尺を計算する（文字数÷話速）
- **出力形式**: `scripts/<id>/script.md`（表：秒数, ナレーション, テロップ, 映像, 出典）
- **完了条件**: 全ブロックが埋まり、尺が規定内で、すべての事実に出典か `【要確認】` がある
- **引き継ぎ**: → R13 台本レビュー（R11・R12の成果物と合わせて）

### R11 タイトル作成
- **目的**: 表紙（カバー）とリール内のタイトル文言を作る。
- **入力**: R07のテーマ、R10の台本
- **作業手順**: 文字数制限【未確定】内で案を作る → NG表現をチェック → 推奨案を決める
- **出力形式**: `scripts/<id>/titles.md`（カバー文言3〜5案、推奨案）
- **完了条件**: 推奨案が決まっている
- **引き継ぎ**: → R13、→ R17 画像生成（カバー用）
- **責任範囲**: 動画内とカバーの文言を担当する。投稿本文はR23。

### R12 CTA設計
- **目的**: 狙うKPIにつながる行動喚起（保存・フォロー・コメント・プロフィール遷移など）を設計する。
- **入力**: R07の狙うKPI、`rules/kpi.md`
- **作業手順**: KPIに対応するCTAを選ぶ → 台本内の配置と文言を決める → キャプション用CTAも案出しする
- **出力形式**: `scripts/<id>/cta.md`（狙うKPI, 動画内CTA, キャプション用CTA, 配置秒数）
- **完了条件**: 狙うKPIとCTAが1対1で対応している
- **引き継ぎ**: → R10（台本に反映）、→ R23 キャプション作成
- **責任範囲**: CTAの「設計」を担当する。キャプション本文へ組み込むのはR23。

## ④ レビュー（3担当は並行し、R13が結果をとりまとめる）

### R13 台本レビュー
- **目的**: 企画意図・構成・面白さ・尺の観点で台本を評価し、修正を指示する。
- **入力**: R10〜R12の成果物、R14・R15の結果
- **作業手順**: チェックリストで採点する → 修正指示を出す（差し戻しは最大【未確定】回）→ R14・R15の結果をまとめる → **オーナーの承認を取る**（承認ゲートG2）
- **出力形式**: `scripts/<id>/review.md`（チェック結果, 修正指示, R14・R15の要約, 判定：OK/差し戻し）
- **完了条件**: R14・R15ともに「指摘ゼロ」、またはオーナーが判断済みで、オーナーが台本を承認している
- **引き継ぎ**: → R16〜R18（確定台本）
- **責任範囲**: 「内容の質」を担当する。事実の正否はR14、表現の適否はR15が判定し、R13は上書きしない。

### R14 事実確認
- **目的**: 台本・キャプション内のすべての事実・数値・引用の正確さを検証する。
- **入力**: 台本、キャプション、出典一覧
- **作業手順**: 事実の主張を一つずつ抽出する → 一次情報で照合する → 判定する（確認済み／誤り／確認できない）
- **出力形式**: `scripts/<id>/factcheck.md`（主張, 判定, 根拠URL, 修正案）
- **完了条件**: 「確認できない」項目は削除されるか、オーナーへの質問として起票されている
- **引き継ぎ**: → R13、確認できない項目は → R28（オーナーへの質問）

### R15 表現チェック
- **目的**: NG表現・法令（景品表示法・薬機法など）への抵触、炎上リスク、トーン違反を防ぐ。
- **入力**: 台本、タイトル、キャプション、`rules/ng-expressions.md`、`rules/tone-and-structure.md`
- **作業手順**: NGリストと照合する → 法令・規約リスクを確認する → トーンの一致を確認する → 言い換え案を出す
- **出力形式**: `scripts/<id>/expression.md`（該当箇所, 理由, リスク度, 言い換え案）
- **完了条件**: リスク度「高」がゼロ
- **引き継ぎ**: → R13、最終文案の確認時には → R23

## ⑤ 素材準備

### R16 素材収集
- **目的**: 映像指示に必要な実写・画像・音源などを、権利を確認したうえで集める。
- **入力**: 確定台本の映像指示
- **作業手順**: 素材リストを作る → 自前素材・フリー素材・購入素材を割り当てる → ライセンスを記録する → 有料素材は**事前に承認を取る**
- **出力形式**: `assets/<id>/assets.csv`（素材名, 用途秒数, 入手元, ライセンス, 費用, ファイルパス）
- **完了条件**: 全カットに素材が割り当てられ、ライセンスが記録されている
- **引き継ぎ**: → R20 動画編集、不足分は → R17・R18
- **責任範囲**: 既存素材の「調達」を担当する。新しく作るものはR17（画像）・R18（図解）。

### R17 画像生成
- **目的**: カバー画像や、既存素材がないカットの画像を生成する。
- **入力**: R11のタイトル、R16の不足リスト、ブランド指定【未確定】
- **作業手順**: プロンプトを作る → 生成する → 実在の人物・商標・誤解を招く表現がないか確認する → AI生成であることを記録する
- **出力形式**: `assets/<id>/generated/`（画像ファイル＋プロンプト記録）
- **完了条件**: 指定サイズ（1080×1920など）で、ブランド指定に沿っている
- **引き継ぎ**: → R20

### R18 図解作成
- **目的**: 数値や手順をわかりやすい図にする。
- **入力**: 台本内の図解指示、R14で確認済みの数値
- **作業手順**: 確認済みの数値だけを使う → スマホで読める文字サイズで作る → 出典を図内か概要欄に記載する
- **出力形式**: `assets/<id>/diagrams/`（画像ファイル＋元データ）
- **完了条件**: 図内の全数値がR14で確認済み
- **引き継ぎ**: → R20

## ⑥ 編集

### R19 字幕作成
- **目的**: 読みやすく、音声なしでも伝わる字幕を作る。
- **入力**: 確定台本、仮編集の音声
- **作業手順**: 文字起こしと台本を照合する → 1行の文字数・表示秒数を整える → 強調語を指定する → 誤字を確認する
- **出力形式**: `edit/<id>/subtitles.srt` と字幕スタイル指定
- **完了条件**: 台本との差異がなく、誤字がゼロ
- **引き継ぎ**: → R20
- **責任範囲**: 「字幕」の担当。台本の文言を変えたいときはR13へ差し戻す。

### R20 動画編集
- **目的**: 素材・字幕・音声を組み合わせ、リールを完成させる。
- **入力**: 確定台本、R16〜R19の成果物、R21の音声
- **作業手順**: カット → テンポ調整 → テロップ・図解を配置 → トランジション → 9:16で書き出す
- **出力形式**: `edit/<id>/draft_vN.mp4`、編集メモ
- **完了条件**: 規定の尺・解像度で、台本どおりの構成になっている
- **引き継ぎ**: → R21（最終音声調整）→ R22

### R21 音声調整
- **目的**: AI音声（TTS）でナレーションを作り、BGM・効果音とのバランスと聞き取りやすさを整える（Q21）。
- **入力**: 編集データ、R04の音源候補
- **作業手順**: 確定台本からTTSでナレーションを生成する（読み間違い・イントネーションを確認し、必要なら読み方を指定して作り直す）→ 尺が台本どおりか確認する → 音量を正規化する → BGMとナレーションのバランスを取る → 音源の利用可否（商用・Instagram内での利用）を確認する
- **出力形式**: 音声調整済みの動画、`edit/<id>/audio.md`（使用音源, 権利, 調整内容）
- **完了条件**: 音割れ・聞き取りにくい箇所がなく、音源の権利が確認済み
- **引き継ぎ**: → R22 品質確認
- **責任範囲**: 「音」の担当。全体の最終判定はR22。

## ⑦ 品質確認・投稿

### R22 品質確認
- **目的**: 公開前の最終チェック。チェックリストに沿って合否を判定する。
- **入力**: 完成動画、確定台本、R14・R15の結果、`rules/quality-policy.md`
- **作業手順**: 映像・字幕・音声・権利・NG・事実・CTA・尺をチェックする → 不合格なら該当担当へ差し戻す → 合格なら**オーナーの承認を取る**（承認ゲートG3）
- **出力形式**: `edit/<id>/qa.md`（チェックリスト結果, 差し戻し履歴, 判定）
- **完了条件**: 全項目が合格し、オーナーが完成動画を承認している
- **引き継ぎ**: → R23・R24

### R23 キャプション作成（Instagram本文＋Threads投稿文）
- **目的**: リールの投稿本文と、同じ企画をThreads向けに作り直したテキスト投稿を作る。
- **入力**: 確定台本、R12のCTA、`rules/ng-expressions.md`、`rules/compliance.md`、`rules/platforms.md`
- **作業手順**:
  1. Instagram：本文を書く（冒頭行を重視）→ CTAを組み込む → ハッシュタグを選ぶ（本数【未確定】）→ 代替テキスト
  2. Threads：台本の要点をテキスト投稿にする（1投稿完結 or スレッド形式）→ 冒頭の1文をフックにする → noteへの導線を入れる
  3. 両方をR15の観点で自己チェックする
- **出力形式**: `post/<id>/caption.md`（Instagram本文, ハッシュタグ, 代替テキスト）、`post/<id>/threads.md`（投稿文, スレッドの分割, リンク位置）
- **完了条件**: 両媒体の文面がそろい、NG表現がなく、CTAが含まれている。Threadsの文字数制限内（制限値はR14が公式情報で確認【要確認】）
- **引き継ぎ**: → R24 投稿管理
- **責任範囲**: Threads投稿の「文面」を担当する。Threads向けの独自企画（リールと関係ない投稿）もR06〜R07の承認を経てR23が書く。

### R24 投稿管理
- **目的**: Instagram・Threadsそれぞれに、適切な日時で正しい内容を投稿する。
- **入力**: 承認済みの動画・キャプション・Threads投稿文、R05のアクティブ時間帯、投稿カレンダー
- **作業手順**: 投稿日時を提案する → **オーナーの最終承認を取る**（承認ゲートG4：投稿の実行）→ Instagram Graph API・Threads APIで投稿する（API連携の準備が整うまでは、素材一式をオーナーに渡して手動投稿を依頼する。`rules/tech-stack.md`）→ 投稿URLを記録する
- **出力形式**: `post/calendar.csv`（id, 媒体, 予定日時, 実投稿日時, URL, ステータス）
- **完了条件**: 投稿URLが記録されている
- **引き継ぎ**: → R25・R26（投稿URLと公開日時）
- **注意**: オーナーの承認なしに投稿・予約は行わない。

## ⑧ 分析

### R25 コメント分析
- **目的**: Instagram・Threadsのコメント・返信・DMから、反応・疑問・不満を抽出する（noteを買う前の不安を特に拾う）。
- **入力**: 投稿URL、コメント本文（API取得 or オーナー提供）
- **作業手順**: 分類する（称賛／質問／要望／批判／スパム）→ 頻出の疑問を抽出する → 返信が必要なものをリスト化する（返信の実行は承認制）
- **出力形式**: `analytics/<id>/comments.md`（分類件数, 代表コメント, 次の企画のヒント, 要返信リスト）
- **完了条件**: 全コメントが分類済み
- **引き継ぎ**: → R27 改善提案、→ R05 視聴者分析

### R26 数値分析
- **目的**: Instagram・Threads・noteの実績を計測し、過去の投稿と比較する。
- **入力**: インサイトの数値（計測タイミング【未確定：24h/7日など】）、`rules/kpi.md`
- **作業手順**: 指標を記録する → 過去平均・目標と比較する → 要因の仮説を立てる（事実と仮説を分けて書く）
- **出力形式**: `analytics/<id>/metrics.md`、`analytics/metrics_db.csv`
- **完了条件**: 規定の全指標が記録され、目標との差分が出ている
- **引き継ぎ**: → R27 改善提案
- **月次タスク**: 有料化判断レポートの数値パートを作る（`rules/note-product.md`）
- **責任範囲**: 「数字の事実と仮説」を担当する。打ち手の提案はR27。

## ⑨ 改善提案

### R27 改善提案
- **目的**: 分析結果を次の企画・ルールに反映する具体策にする。
- **入力**: R25・R26の出力、過去の改善ログ
- **作業手順**: 良かった点と課題を整理する → 改善策を出す（担当・工程・ルールのどこを変えるか）→ ルール変更案は**オーナーの承認後**に `rules/` を更新する
- **出力形式**: `analytics/<id>/improvement.md`（事実, 仮説, 施策, 対象担当, 優先度, 検証方法）
- **完了条件**: 施策ごとに検証方法がある
- **引き継ぎ**: → R06 企画立案（次サイクル）、→ R28（ルール変更の起票）
- **月次タスク**: 有料化判断レポートのまとめと提言を作る（決定はオーナー）

## 全工程

### R28 進行管理
- **目的**: 依頼の受付、必要情報の確認、各担当への振り分け、承認ゲートの管理、納期の管理。
- **入力**: オーナーの依頼、`workflow/reel-production.md`
- **作業手順**:
  1. 依頼票（`templates/reel-request.md`）の必須項目を確認し、不足していればオーナーへ質問する
  2. 案件IDを発行し、工程表を作る
  3. 各担当へ引き継ぎ票で依頼する
  4. 承認ゲート（G1〜G4）ごとにオーナーへ承認を依頼する
  5. 差し戻し・遅延・質問事項をまとめて報告する
  6. 毎週：オーナーに実践の記録（やったこと・時間）を聞き取る／毎月：有料化判断レポートを提出する
- **出力形式**: `projects/<id>/status.md`（工程, 担当, 状態, 期限, ブロッカー, オーナーへの質問）
- **完了条件**: 投稿が完了し、分析・改善提案の担当へ引き継がれている
- **引き継ぎ**: 全担当
